# ЭП: Кошелёк ресурсов — концепция

## Зачем

Существующее мобильное приложение «Помощник купца» (`merchant_mobile_helper.html`) было калькулятором без привязки к конкретному игроку: экраны Цены/Рынок/Производство просто считают числа, не трогая бэкенд по конкретному игроку.

По ТЗ (`Доработка калькулятора купцов - ТЗ.md`) приложение дорабатывается до полноценного «ЭП: Кошелёк ресурсов»: игрок один раз привязывает телефон к своему персонажу, видит свои ресурсы (иконка + количество), синхронизированные с бэком, и может передать часть ресурсов другому игроку. Старые экраны калькулятора остаются без изменений — «Кошель» добавлен как ещё один пункт главного меню.

Это первый шаг на пути к более полноценному мобильному приложению (в перспективе — сканирование QR-кодов и push-уведомления), поэтому PWA-обвязка сделана через `vite-plugin-pwa`, а не руками — чтобы не переезжать на другой инструмент позже.

## Пользовательские сценарии

### 1. Первый запуск — выбор игрока
1. Игрок открывает приложение на телефоне впервые.
2. Вместо главного меню показывается экран «Кто вы?» со списком всех игроков (с поиском по имени).
3. Игрок находит себя и подтверждает выбор («Сменить игрока после подтверждения будет нельзя»).
4. Выбор сохраняется на устройстве (`localStorage`). При следующих запусках экран выбора не показывается — сразу открывается главное меню.

### 2. Просмотр кошеля
1. В главном меню — пункт «Кошель».
2. Открывается сетка ресурсов игрока: иконка + название + количество, только те ресурсы, которых больше нуля.
3. Данные всегда запрашиваются заново с бэка при открытии экрана — старое значение никогда не показывается из кэша.

### 3. Установка на экран

При открытии приложения (на `calc.igroteh.su` или где угодно ещё, где отдаётся манифест) браузер в какой-то момент решает, что приложение можно установить, и сообщает об этом через событие `beforeinstallprompt`. Вместо стандартного баннера браузера показывается собственный — синяя плашка сверху экрана «Установить приложение» с кнопкой «Установить» (и крестиком, чтобы закрыть на этот раз). Плашка видна на любом экране приложения, включая экран выбора игрока — ставить приложение можно даже до того, как выбран игрок.

### 4. Передача ресурсов другому игроку
1. На экране кошеля — кнопка «Передать».
2. Шаг «Кому»: список остальных игроков (кроме себя), поиск по имени.
3. Шаг «Корзина»: список ресурсов отправителя с текущими остатками, для каждого — степпер +/-, нельзя выбрать больше, чем есть в наличии.
4. Шаг «Подтверждение»: кому и что передаётся, кнопка «Подтвердить».
5. После подтверждения бэкенд атомарно списывает ресурсы у отправителя и начисляет получателю; при ошибке (например, кто-то уже потратил ресурс с другого устройства) — показывается сообщение об ошибке без потери выбранной корзины.
6. После успешной передачи — возврат на экран кошеля с обновлённым балансом.

## Ключевые решения

- **Аутентификация — только на устройстве.** Бэкенд не ведёт отдельную сессию для мобильного кошелька (`/auth/login` не используется). Выбранный `id`/`identificator` игрока хранится в `localStorage` и передаётся явно в каждом запросе (`/players/:id/...`) — так же, как это уже делают остальные mobile-помощники в проекте.
- **Смена игрока запрещена.** В интерфейсе физически нет пункта «сменить игрока» — это соответствует требованию ТЗ.
- **PWA через `vite-plugin-pwa` (`injectManifest`).** Выбрано вместо ручного `sw.js`, потому что в будущем планируются push-уведомления и более сложная логика service worker — Workbox уже даёт готовые примитивы (`precacheAndRoute`, `cleanupOutdatedCaches`), которые пригодятся при развитии.
- **PWA не кэширует данные бэкенда.** Service worker прекэширует только собственные статические ассеты приложения (JS/CSS/иконки). Запросы к `${VITE_PROXY}/...` не описаны в precache-манифесте и никогда не перехватываются — баланс ресурсов всегда живой, даже при установленном PWA.
- **Старый функционал калькулятора не тронут.** Цены/Рынок/Производство — те же компоненты, те же экраны; «Кошель» — независимый 4-й пункт меню.
- **`calc.igroteh.su` — основной домен установки.** Приложение деплоится отдельно на `calc.igroteh.su` (см. `era_scripts/deploy-frontend.sh`, каталог `/opt/era/mer_calc`), где `merchant_mobile_helper.html` переименовывается в `index.html` и раздаётся с корня домена. Поэтому `start_url` в манифесте — `/`, а не `/merchant_mobile_helper.html`. Это значит, что при установке со вторичного пути `epoha.igroteh.su/merchant_mobile_helper.html` иконка на экране открывала бы `epoha.igroteh.su/` (админку) — известное ограничение, не решается без раздельных манифестов на деплой.
- **Своя плашка установки вместо системного баннера.** Событие `beforeinstallprompt` перехватывается (`event.preventDefault()`), чтобы показать собственную кнопку «Установить» в фирменном стиле приложения, а не дефолтный баннер браузера.

Технические детали (эндпоинты, файлы, формат хранения, устройство service worker) — в `Кошелек ресурсов - детали реализации.md`.
